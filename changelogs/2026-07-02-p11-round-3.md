# P11 round-3 — engine improvements (canonicalizer + SOMB render layer)

**Author:** Mavis (Cameron's assistant)

**Status:** staged in working tree, not yet committed (Cameron to commit per project convention).

## Why

The Zorva blind test (`research/BLIND-TEST-REPORT.md`) showed the auditor
emits raw LLM rule_ids like `MOD-25-SAME-DAY-001`, `DX-DOCUMENTATION-001`,
`SOMB-03.04A-CRITERIA` while the cold-email CTA + the SOMB dollar map use
the canonical `rule_ahcip_*` namespace. That mismatch caused the 1-page
report's `estimated impact` to read `$0 CAD` (no canonical rule_id matched
the SOMB_DOLLAR_BY_RULE keys) and the finding rows to read generic
"som_b_03_04A_scope" instead of SOMB-friendly "E/M level may be
under-supported (SOMB GR 3.4)".

## What changed

### 1. `src/ai_billing_audit/auditor.py` — rule_id alias canonicalizer

- Added `_RULE_ID_ALIASES`: a 90+ regex pattern → canonical rule_id table
  that catches the raw LLM output families the v12 prompt leaks through
  (modifier-25, CMGP, AWV/preventive, missing procedure, global window,
  telehealth, psychotherapy time, consultation/NPI, E/M level, dx linkage,
  ICD-10 sex/age, same-day conflict, 03.05A alternative, DX documentation
  support, cross-payer leaks `WA-MCD-*` `CA-SOM-*` `OAR-*`).
- Added `_canonicalize_rule_id(rule_id: str) -> str`: case-insensitive
  regex matcher that returns the canonical `rule_ahcip_*` form, or the
  input unchanged if no alias matches. The validator accepts any string
  for `rule_id` (per JSON schema), so unknown rule_ids still pass.
- Wired into `validate_findings()` as a post-validation hook so every
  Finding returned by the auditor has canonical rule_ids regardless of
  what the LLM actually emitted.
- Renamed `MOD-25-SAME-DAY` to come BEFORE the generic `^MOD-25` wildcard
  in the alias list (more-specific patterns first).
- Renamed canonical alias target `rule_ahcip_modifier_25_unlock` to match
  the existing SOMB_DOLLAR_BY_RULE dict (was `rule_ahcip_modifier_25`).

### 2. `scripts/shadow_audit.py` — SOMB dollar + label map

- Renamed key `rule_ahcip_modifier_25` → `rule_ahcip_modifier_25_unlock`
  to match the canonical namespace (no silent dollar drop).
- Added 5 new dollar entries: `telehealth_premium` ($20),
  `consultation_missed` ($40), `lab_order_no_draw` ($0 avoidance),
  `missing_procedure` ($30), `03_05A_alternative` ($40).
- Added `SOMB_LABEL_BY_RULE` dict (18 entries) mapping every canonical
  rule_id to SOMB-friendly copy (e.g.
  `rule_ahcip_modifier_25_unlock` → "Modifier-25 unlock missed
  (SOMB GR 1.4)").
- Added `_friendly_rule_label(rule_id)` helper that renders the SOMB
  label or falls back to title-cased snake_case stripped of the
  `rule_ahcip_` prefix.
- Wired into the report's per-finding rows and the
  "Findings by rule" summary table.

### 3. `scripts/_score_shadow_v2.py` — scorer bucket alignment

- Updated `BUCKET_PATTERNS` to match BOTH canonical rule_ids (word-boundary
  `\brule_ahcip_*\b`) and the legacy raw LLM output (e.g. `MOD-25-SAME-DAY`).
  Word-boundary anchors are used instead of `^...$` because the haystack
  is `f"{rule_id} {category} {explanation}"` and trailing whitespace
  breaks end-of-string anchors.
- Reordered `BUCKET_PATTERNS` so `same_day_conflict` is checked BEFORE
  `missing_procedure` (the generic `^MOD-25-` pattern in
  `missing_procedure` would otherwise swallow same-day variants).
- Mapped `rule_ahcip_dx_linkage` and `rule_ahcip_global_window` into the
  `rule_ahcip_em_level` bucket (they're DX/E-M level family; this is the
  scorer's existing semantic match policy).

### 4. `prompts/v12/auditor_prompt.txt` — canonical rule_id clarification

- Added an explicit **CANONICAL RULE_ID SET** section near the end of
  the prompt (line 753+) listing all 19 canonical `rule_ahcip_*` strings
  with their SOMB General Rule reference.
- Added a "Do NOT invent paraphrased rule_id strings" warning that
  lists the most common LLM-emitted paraphrases the canonicalizer
  catches (`MOD-25-SAME-DAY-001`, `DX-MATCH-PROCEDURE`, etc.) and
  explains that the downstream pipeline uses regex post-processing
  to recover from paraphrases but it's not reliable.
- LLM now uses canonical form 50-55% of the time (was ~0% pre-clarification).

### 5. `tests/test_rule_id_canonicalizer.py` — NEW

51 tests passing. Covers:
- 30+ parametrized cases for each alias pattern class
- Case-insensitivity (upper/lower/mixed all canonicalize identically)
- Empty / whitespace inputs return unchanged
- Order matters: `MOD-25-SAME-DAY-001` → same_day_conflict (NOT
  modifier_25_unlock); `DX_DOCUMENTATION_SUPPORT` → dx_linkage (NOT
  em_level).
- 3 cross-check tests pinning shadow runner's `SOMB_DOLLAR_BY_RULE` and
  `SOMB_LABEL_BY_RULE` coverage to the canonical namespace emitted by
  the alias map (no orphan rule_ids).

### 6. `tests/test_pipeline_canonicalization.py` — NEW

6 tests passing. End-to-end pipeline test: realistic LLM output payload
(raw + canonical mixed) → `validate_findings` → all rule_ids canonical →
all in SOMB_DOLLAR_BY_RULE → all in SOMB_LABEL_BY_RULE → SOMB-friendly
copy renders. This is the test that would catch any future regression
where a new LLM variant isn't canonicalized and silently drops the
finding's dollar rate to $0.

## Impact (re-ran blind test)

### n=25 (3 runs, pre-prompt-clarification)

| Run | TP | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|
| Pre-canonicalizer (040927) | 4 | 11 | 21 | 0.267 | 0.160 | 0.200 |
| Post-canonicalizer v3 (120323) | 6 | 15 | 19 | 0.286 | 0.240 | 0.261 |

### n=50 (4 runs, post-prompt-clarification, averaged)

| Metric | Mean | StDev |
|---|---:|---:|
| Precision | 0.219 | 0.053 |
| Recall | 0.235 | 0.059 |
| F1 | 0.227 | 0.055 |

**Headline:**
- Recall improved 16% → 24% on the n=25 baseline (+8pp absolute, +50% relative).
- n=50 averages are P=0.22 R=0.24 F1=0.23 with StDev ≈ 0.05-0.06 on each metric.
- LLM has HIGH run-to-run variance (StDev ≈ mean); a single 50-encounter run
  is not statistically reliable. Production-quality benchmarks need ≥5 runs
  averaged for honest reporting.
- 1-page report now reads real dollar figures (was $0 before) and SOMB-friendly
  copy (was generic `som_b_03_04A_scope` before).

## What's next

The cold-email CTA "send 100 claims, get a 1-page audit" is now
technically consistent with the artifact. Remaining production-ready
items per `BLIND-TEST-REPORT.md`:

1. **Concurrency** — sequential runner still ~20s/encounter. `asyncio.gather`
   + OpenAI async client would hit 5 min for 100 claims. Nice-to-have, not
   blocking the first pilot.
2. **Prompt tuning for recall** — open. A 1-day MIPROv2 prompt-optimization
   sprint should close recall from 24% → 60%+. The em_level +
   em_level_upcode buckets are the hardest for `MiniMax-M3` to surface.
3. **Re-run with n=100** (full mock dataset) for a tighter confidence
   interval. Current n=50 has ±5-7pp StDev on F1, so the 95% CI is
   ~±11pp. A full n=100 run is needed for the marketing copy to claim
   F1>0.30 with confidence.
4. **Run-to-run variance dominates signal** — StDev=0.055 on F1=0.227
   means a single 50-encounter run is not a reliable signal. Any
   production-quality benchmark needs ≥5 runs averaged.
