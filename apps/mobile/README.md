# apps/mobile — Zorva Audit (Capacitor wrap)

Kanban card **t_7004415a** — "iOS / Android app (Capacitor wrap of
the dashboard)".

This is a **scaffold**. The native builds (`ios/`, `android/`)
require Xcode + a Mac for iOS, and Android Studio for Android.
The scaffold ships the Capacitor project layout, configuration
pointing at the live dashboard, and the dependency manifest.

## What it does

The Capacitor WebView loads the live Zorva dashboard at
**https://zorva.ashbi.ca/**, so any update shipped to
the web dashboard is immediately visible in the wrapped app —
no App Store / Play Store resubmission needed for a content
change.

The native shell adds:

* **@capacitor/app** — handles the iOS / Android back button
  correctly (Web back navigation when possible, app exit when
  the Web stack is empty).
* **@capacitor/preferences** — persisted settings (e.g. "stay
  logged in" tokens) survive app restarts and reinstalls.

## Layout

```
apps/mobile/
├── README.md           — you are here
├── package.json        — Capacitor deps (@capacitor/core,
│                         @capacitor/ios, @capacitor/android,
│                         @capacitor/app, @capacitor/preferences)
├── capacitor.config.json — WebView target, plugin config
└── www/
    ├── index.html      — local splash + JS redirect to the
    │                     dashboard URL (fallback only)
    └── zorva-mark.svg  — local accessible fallback mark
```

The `ios/` and `android/` directories are **not** checked in —
they're generated by `cap add ios` / `cap add android` and
contain machine-specific build artifacts (Xcode project,
Gradle wrappers, etc).

## Build commands

These commands require a Mac for iOS, and either a Mac or a
Linux/Windows host with Android Studio installed for Android.

```bash
cd apps/mobile

# 1. Install the JS deps.
npm install

# 2. Add the iOS native project (requires Xcode + a Mac).
#    Skipped on the first run if ios/ already exists.
npm run add:ios          # equivalent to: npx cap add ios

# 3. Add the Android native project (requires Android Studio).
#    Skipped on the first run if android/ already exists.
npm run add:android      # equivalent to: npx cap add android

# 4. Copy the latest www/ + capacitor.config.json into the
#    native projects. Run this after every change to either
#    file.
npm run sync             # equivalent to: npx cap sync

# 5. Open the native IDE to build + run.
npm run open:ios         # equivalent to: npx cap open ios
npm run open:android     # equivalent to: npx cap open android

The raw `cap` commands also work directly (without the npm
script wrappers):

```bash
npx cap add ios          # one-time: scaffold the ios/ directory
npx cap add android      # one-time: scaffold the android/ directory
npx cap sync             # copy www/ + capacitor.config.json to native projects
npx cap open ios         # open the Xcode workspace
npx cap open android     # open the Android Studio project
```
```

From Xcode / Android Studio you build a release artifact the
usual way (`Product → Archive` on iOS, `Build → Generate Signed
APK / AAB` on Android) and submit to App Store Connect / Google
Play Console.

## Updating the dashboard URL

If the marketing site moves, edit `capacitor.config.json`:

```json
"server": {
  "url": "https://NEW-URL/",
  "cleartext": false,
  "androidScheme": "https"
}
```

Then run `npm run sync` to push the new config to the native
projects.

## Why Capacitor (vs React Native / Flutter)

* The dashboard is already a Next.js web app; wrapping it in
  Capacitor means every feature shipped to the web is also
  shipped to the mobile app, with zero duplication.
* The Capacitor WebView is a real browser (WKWebView on iOS,
  Chromium WebView on Android), so the responsive dashboard
  renders correctly out of the box.
* App Store / Play Store compliance is straightforward for a
  WebView wrap that loads first-party content.

## What's NOT in this scaffold

* No push-notification plugin yet. When the kanban card for
  push lands, add `@capacitor/push-notifications` to
  `package.json` + run `npm run sync`.
* No biometric / secure-storage plugin. The dashboard's
  session cookie is what auth uses; add `@capacitor/secure-
  storage` if the team needs to harden it for the iOS
  Keychain / Android Keystore.
* No CI workflow. When the team is ready, add a GitHub Actions
  job that runs `npm run sync` then `xcodebuild` / `gradle
  bundleRelease`.

## Verification

The scaffold ships with a smoke check in
`tests/test_mobile_scaffold.py` that asserts:

* `package.json` is valid JSON.
* `package.json` declares the five required Capacitor deps.
* `capacitor.config.json` is valid JSON.
* `capacitor.config.json` points at the live dashboard URL.
* `www/index.html` exists and contains the splash markup.

Run it with:

```bash
.venv/bin/python -m pytest tests/test_mobile_scaffold.py -v
```
